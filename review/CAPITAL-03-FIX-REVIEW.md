# CAPITAL-03-FIX — Review

Дата: 2026-11-25  
Public: https://github.com/UberSerg/live-harvest-ui

## Первопричина

«Факт-поток периода» считался как **экономическая** аналитика (`consumer_only`: без `needs_review`, переводов, инвестиций и т.п.), а пользователь сверял его с **банковскими итогами** выписки (все пополнения/списания).  
Это не ошибка суммирования копеек в парсере для подтверждённых покупок, а смешение двух разных метрик в одном KPI.

## Что исправлено

1. Парсер извлекает footer `Пополнение` / `Списание` и сверяет с суммой распознанных операций **до** классификации (до копейки).
2. При `mismatch` импорт пакета **не сохраняется**; показывается диагностический статус.
3. UI разделён:
   - **Банковский оборот** — все actual поступления/списания/net;
   - **Экономическая аналитика** — доходы/расходы/типы; drill-down по клику.
4. Doughnut = только экономические расходы; блок «Вне графика» с причинами исключения.
5. `POST /api/import/repair` — чинит metadata существующих bank_import без повторной загрузки текста.
6. Статус сверки в UI: matched / mismatch / no_totals.

Синтетический 30-page фикстур дополнен footer-итогами; сверка matched.

## Существующие импорты

- Repair обновляет batch reconciliation из сохранённых операций.
- Если footer не был сохранён ранее → статус «Итоги выписки отсутствуют»; оборот строится из операций.
- Повторный импорт той же выписки безопасен (fingerprint dedupe) и запишет footer + matched при полном тексте.

## Privacy

Отчёт без персональных сумм. Сырой текст выписки по-прежнему не хранится.
